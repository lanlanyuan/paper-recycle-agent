## 关键决策记录（ADR 摘要）

**#15 为什么下线市、县两级**
市级、县级废纸回收量没有公开的权威统计。v1.2 用权重分摊生成市县数据，虽然能让「下钻」看起来完整，
但使用者无法分辨哪些是真实数字。与其给出看起来精确、实际是编造的数据，不如明确只给两级并标注数据性质。
这是本项目最重要的一次「减法」。

**#16 为什么分类数据标注为「估算」**
GB/T 20811-2018 只规定分类技术要求，官方不逐类公布回收量。因此分类回收量只能是
「结构占比 × 官方回收量」，占比本身来自行业经验值。全部字段带 `provenance`，界面与 Excel 都写明，
避免被当成统计公报数据引用。

**#23 为什么把下限降到 3.7，而不是干脆支持 3.6**
全仓库唯一的版本门槛是 `dataclasses`（3.7 引入），没有用到 walrus、`match`、`removeprefix`、
`zoneinfo` 等更高版本特性。降到 3.7 是零成本的；要再降到 3.6 就得把两个 dataclass 改写成
普通类，收益不足以抵消可读性损失。更重要的是：**声明支持哪个版本，就必须有办法验证**，
所以同时引入了 `tools/check_compat.py`，用 3.7 语法树解析全部源码并扫描 3.8/3.9 专有 API，
CI 每次都会跑。没有校验的版本声明只是一句口号。

**#24 为什么 openpyxl 必须变成可选依赖**
原实现在 `exporter.py` 顶层 `from openpyxl import ...`，而 `__init__.py` 又 import 了 exporter，
结果是「没装 openpyxl」这台机器连 `import paper_recycle_agent` 都会失败——命令行、离线版全部不可用。
改成按需导入后，缺依赖只影响导出这一个动作，且失败信息从 500 堆栈变成
「执行 pip install openpyxl，或改用离线版」这样的可执行指引。

**#25 为什么启动脚本里一个中文都没有**
实测两种写法都不可靠：`.bat` 由 cmd.exe 按控制台代码页逐行解析，UTF-8 中文会切断语句
（`!PYEXE!` 被拆成 `e`、`exe` 去执行）；给 UTF-8 文件加 BOM 则会让首行变成「BOM + @echo off」，
`@echo off` 直接失效、每行都回显。GBK 编码在中文系统上能用，但一旦系统开了
「Beta: 使用 Unicode UTF-8」就又崩。唯一在任何语言环境下都安全的做法是**纯 ASCII 脚本**，
中文说明放到 README / USAGE 里。
