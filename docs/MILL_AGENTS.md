# 造纸工艺全流程智能体（仿真版）· 架构与开发说明

> 版本：v1.7.0 · 分支：`feature/mill-agents`
> 系列：「废纸回收 Agent 对话助手」的连续开发延伸

## 一、先说实话：GitHub 上有没有现成的"造纸工艺大模型"？

没有。至少公开仓库里没有可直接用的。

调研结论（2026-11-22，逐条可复查）：

| 名称 | 性质 | GitHub 公开仓库 |
| --- | --- | --- |
| 广州博依特「工艺大模型」 | 闭源商用，华南理工刘焕彬院士团队孵化 | 无 |
| 山东华泰「产业大脑」五个大模型 | 企业自研自用 | 无 |
| Smurfit Kappa 英国汤森德胡克厂干燥数字孪生 | 企业项目，论文/新闻有报道 | 无 |
| `classproject-papermakingsimulator/papermaking-simulator` | 西安交大课程作业，Unity + VR 古代造纸教学 | 有，2 star，仅流程演示，无 AI |
| `xbpaper/Papermaking-Skills` | 中文造纸技能条目 | 有，1 star，无代码价值 |
| `glbramalho/PLANTsim` | 工业过程数字孪生教学框架，Python + MODBUS TCP | 有，8 star，可参考其"过程建模 + PLC 对接"思路 |

**判断**：垂直造纸大模型的知识壁垒在企业与高校手里，不会开源。但"多智能体编排"的骨架是通用的，可以自己搭——这正是本模块做的事。架构范式参考 `TradingAgents`（多角色分工 + 工具调用，123k star）的分层思路，过程建模思路参考 `PLANTsim`。本仓库未复制这两者的代码，只借鉴分层思想。

## 二、这个模块做了什么

在原有废纸回收助手里新增一个「智能工厂」标签页，把造纸流程拆成四道工序，每道工序由一个子智能体负责，顶层由总调度器（Orchestrator）编排：

```
               总调度智能体 Orchestrator
           （任务分解 / 工序编排 / 异常仲裁）
                         │
      ┌──────────┬───────┴───────┬──────────┐
   制浆智能体   抄纸智能体     干燥智能体    质检智能体
   碎浆脱墨漂白  流送成形压榨   蒸汽优化孪生  视觉检测抽检
      │            │              │            │
   AGV/PLC      PLC/AGV      PLC/机器狗   机器狗/PLC
      └──────────┴───────┬───────┴──────────┘
                设备执行层（全部内存模拟）
```

代码位置：`src/paper_recycle_agent/mill/`

| 文件 | 职责 |
| --- | --- |
| `processes.py` | 四道工序定义：工况参数、正常区间、责任设备、专家知识 |
| `simulation.py` | 确定性仿真引擎：状态机、工况生成、异常注入、工序流转 |
| `devices.py` | 设备层 mock：AGV / 巡检机器狗 / PLC，统一 `assign(task)` 接口 |
| `agents.py` | `ProcessAgent` 工序智能体 + `Orchestrator` 总调度器 |

## 三、安全边界（必须说清楚）

**这是仿真，不是工业控制系统。**

- 工况数据由仿真引擎按工艺常识区间生成，不是任何真实产线的实测值；
- AGV / 机器狗 / PLC 都是内存中的模拟对象，不连接任何硬件，不发 MODBUS / OPC UA 指令；
- 真实工厂里 AI 不应直接下发控制指令——必须经过联锁逻辑、安全认证与人工复核。本模块把设备层刻意做成 mock，就是这条边界的体现；
- 质检智能体的建议也只作提示，判废与放行由人工确认。

将来若接真实设备，只需替换 `devices.py` 的实现（接口形状一致），上层多智能体框架不用改——但那是另一个需要硬件与安全评审的工程，不在本项目范围内。

## 四、复用了现有代码

- **大模型调用**：直接复用 `llm.py`。配置了 API Key 时，工序智能体用大模型给处置建议；未配置时自动回落规则引擎（知识库规则），保证零依赖可用；
- **决策可追溯**：每条决策都带 `basis` 字段（`rule` / `llm`），前端明确标注"规则引擎"还是"大模型"，不把模型建议伪装成确定结论；
- **Web 服务**：在 `app/server.py` 挂 7 个 `/api/mill/*` 接口，前端在 `index.html` 加一个标签页，与原有七个标签页并存。

## 五、接口一览

| 接口 | 作用 |
| --- | --- |
| `GET /api/mill/processes` | 四道工序定义（参数区间、责任设备、专家知识） |
| `GET /api/mill/state` | 当前仿真快照（工序 / 设备 / 决策 / 日志） |
| `POST /api/mill/start` | 投一个新生产批次 |
| `POST /api/mill/step` | 推进 N 个仿真步（上限 60） |
| `POST /api/mill/run` | 自动跑到流水线空闲 |
| `POST /api/mill/anomaly` | 注入异常（如把白度强制设为 20），演示智能体处置链 |
| `POST /api/mill/reset` | 重置仿真 |

## 六、怎么演示

1. 启动服务：`pip install -r requirements.txt` → 双击 `启动本地版.bat` 或 `uvicorn app.server:app`
2. 打开「智能工厂」标签页，点「投批次」，再点「自动跑完」——四道工序依次完成，7 台设备轮流作业，日志滚动；
3. 点「重置」，再投批次，在「异常注入」选「制浆 / 白度」填一个越界值（如 30），点「注入异常」再跑——会看到制浆工序被挂起、触发仲裁、派机器狗巡检的完整链条；
4. 在「设置」里配了大模型 API 后重跑，「智能体决策」会标注 `[大模型]`；不配就是 `[规则引擎]`。

## 七、数据口径

工况区间取自制浆造纸工艺的公开常识（浆浓 2.5–4.5%、车速 600–900 m/min、成纸水分 5–7% 等），**仅作仿真演示的合理数值范围**，不对应任何具体工厂、机组或产品标准。测试用固定 seed（默认 2024），同样的种子产生同样的工况序列，便于复现与评审。
